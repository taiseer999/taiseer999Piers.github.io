v3.2.17
- Auto-patch watchdog no longer waits for repository relinking: with an empty
  repo cache the relink retries for up to 3 minutes and held the watchdog back
  (log 2026-10-04: service up 12:15:38, watchdog only 12:18:45). Relinking now
  runs in the background.

v3.2.16
- Every restart now goes through ABUKARIM Wizard > Maintenance > Force Close
  (plugin mode 18). The clean Quit / RestartApp hung on Kodi 22 ("Stopping the
  application..." forever, log 2026-10-04 12:14). Used by the update prompt,
  Origin Fix, Device Tuning, tab toggle and the add-on DB rebuild (desktop).
  If the wizard is missing or does not act within 5 s, Kodi is exited directly
  (same thing the wizard does). CoreELEC brings Kodi back by itself.
- Update prompt now appears right when ABUKARIM TOOLS is updated while Kodi is
  running (checks addon.xml every 20 s, waits until nothing plays and no
  dialog is open), not only on the next boot.
- The service frees its heartbeat when it stops and a new copy waits 15 s for
  the old one, so an updated service is no longer turned away as a duplicate.

v3.2.15
- FIX: auto-patching stopped because the service never got going at boot.
  The service, the watchdog and i18n all called xbmcaddon.Addon() at import;
  with the damaged Addons33.db ("Can't update database Addons33 from version
  0") that call can block at boot, so the service hung before its first log
  line. Import-time paths/version now come from special:// paths
  (resources/lib/paths.py); Addon() is only created on first real use.
- First line of service.py logs "[AbukarimTools Service] process started"
  before anything else - shows whether Kodi launched it at all.
- Guardian: if the service it kicked still has no heartbeat after 45 s, the
  guardian runs the auto-patch watchdog + window rescue itself.

v3.2.14
- FIX: since 2026-10-04 Kodi 22 never started the ABUKARIM TOOLS service at
  boot (no "[AbukarimTools Service] started" line in any log; DexHub and Last
  Played were skipped too - that is also why Last Played recorded nothing).
  Without the service there was no watchdog and no window rescue, so the AF3
  update froze again. New guardian.py: AF3 Home runs it once per session
  (always-on Home.xml onload patch); it waits 25 s and starts every watched
  service whose heartbeat is missing (ABUKARIM TOOLS, Last Played (ABUKARIM)),
  and logs when one of them is disabled.
- Window rescue now starts first thing in the service, before the boot chores.

v3.2.13
- FIX: black screen / "frozen" Kodi every time the ACTIVE skin updates
  (AF3 5.10.25 -> 5.10.26, log 2026-10-04 07:15). Kodi unloads the skin
  before extracting the update, then ReloadSkin restores "the window that was
  open" - which by then is none, so the new skin loads with no window at all
  and TMDbHelper floods the log with "Window id does not exist". A small
  service thread now spots an invalid current window lasting 4 s and opens
  Home (15 s cooldown, idle for the first 20 s of boot).

v3.2.12
- Last Played fix now covers EVERY video add-on, not just TMDbHelper flows.
  While you browse, the service remembers the last 8 playable add-on items
  you focused (also over AF3's windowed trailers). When a stream starts, the
  one that matches it (TMDb/IMDb id first, then exact title / show+SxE) is
  saved as the replay link, and the list shows that add-on as the source -
  Seren, Umbrella, POV, Fen Light, anything. "Sources as folder" entries can
  no longer win over the real title. Fallbacks unchanged: TMDbHelper link
  from ids, then the raw stream. Toggle renamed "Record Streams (all video
  add-ons)".

v3.2.11
- NEW Toggles > "Last Played: Record Streams (TMDbHelper/Fen Light)" (on by
  default). Last Played 6.4.0 never recorded TMDbHelper -> Fen Light playback:
  the dummy.mp4 splash fired its stop with empty data, the real stream was read
  before its info settled and anything not typed movie/episode was dropped.
  The service is replaced: capture on onAVStarted, dummy + AF3 trailers
  ignored, internet items classified from their TMDb/IMDb ids, entry saved at
  start (survives a crash/power-off) and stored as a TMDbHelper play link so it
  replays after the debrid link expires. Restarted automatically after patching.
- NEW Toggles > "a4kSubtitles: Hide Account/API-Key Nags" (on by default).
  OpenSubtitles / SubDL / SubSource without accounts no longer pop
  "requires authentication / API Key" (and "IMDB ID is not provided") on every
  search - they go to the log. a4k's debug chatter (player_props dumps,
  "no subtitles found for ...") is written only when Kodi debug logging is on.

v3.2.7
- NEW remote patch flag "once": the entry is applied a single time per box
  (recorded by its "id" in patches_once.json) and skipped afterwards, so a
  whole-file replacement (inject_file + replace) no longer reverts later user
  or menu-reconcile edits on every sweep. Publish a newer file under a new id.
- repo_validate.py: "once" needs an "id"; warns on replace without "once".

v3.2.6
- NEW remote "json_edit" patches: edit JSON files by matching items on their
  fields (guid / label / "~substring") instead of text, so formatting
  differences between boxes don't matter. Ops: match+set/unset, remove,
  append/insert (idempotent via "unless"), move before. Works on add-on files
  and, with "base": "addon_data", on userdata (e.g. script.skinvariables
  nodes). A changed node of the active skin triggers a template rebuild.
- Patching > Update Online Fixes & Catalogs now applies the downloaded
  patches immediately and shows the result.
- repo_validate.py checks json_edit entries.

v3.2.4
- FIX (video 2026-10-03 09:49, AF3 power tray: empty slot, Force Close red in
  the editor): menu_reconcile asked System.HasAddon() whether
  plugin.program.ABUKARIMwizard is installed. Kodi lowercases condition
  strings, so a mixed-case id never matches (same root cause as
  wizard_runner 3.1.3) and the item was hidden. Mixed-case ids are now checked
  through JSON-RPC Addons.GetAddonDetails (installed + enabled); items hidden
  by mistake come back on the next boot or with Repair Menus & Widgets.
- Skin conditions are never generated for mixed-case ids (they could only
  ever evaluate false); bootstrap uses the same presence check.

v3.2.3
- FIX (log 2026-10-03 09:40, AF3 power tray "Skin Variables error", 0 items,
  could not edit): menu_reconcile tagged the items it hid with
  "abk_hidden": [ids] - a LIST. skinvariables passes every item field to
  ListItem.setProperties(), which only takes strings, so any node holding a
  hidden item raised TypeError and the whole menu failed. The tag is now a
  comma-separated string; list tags written by 3.2.0-3.2.2 are converted on the
  next boot (or Maintenance > Repair Menus & Widgets) and the skin's
  templates are rebuilt.

v3.2.0

  are read from taiseer999Piers.github.io/abukarim/ (refreshed at boot, max
  every 6 h, cache-only everywhere else). Patches can now be added or killed

  (dev paths rewritten to special://home) + restore a profile backup.
- NEW Menu reconcile: menu items / widgets that point at an add-on that is not
  installed are hidden (skinvariables: disabled flag, skinshortcuts v3:
  System.HasAddon visible) and come back automatically once it is installed.
  Runs at boot and after the Add-on Portal; also in Maintenance.
- NEW First run: setup preset (Full / Lite / Plex-Emby / Custom) pre-ticks the
  Add-on Portal; device tuning sizes the video cache from RAM; every box gets
  its own web server password (shown once with a QR for Kore/Yatse); thin-build
  bootstrap installs add-ons listed in bootstrap.json from their repos.
